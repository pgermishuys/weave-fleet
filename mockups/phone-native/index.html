Native feel

Mockups of Fleet's phone app that feel like an iPhone or Android app, not a web page. They're real and touch-driven: drag the sheets, swipe back, pull to refresh. Nothing talks to Fleet; it's all pretend data.

Open the app mockup

Best on your phone. For the full effect add it to your Home Screen first (Safari: Share, then Add to Home Screen; Chrome: menu, then Add to Home screen) and open "Fleet mock" from there: full screen, no browser bars, and swipe back without Safari's own gesture getting in the way.

Decisions for you

1. One look, or each platform's own?

  1. Follow each platform: iOS 26 glass bars on iPhone; Material 3 on Android (back arrow, flat tab bar with a pill, a New session button at the bottom right, Material switches, ripples)
  2. The iPhone look everywhere
Recommend 1. Same screens and layout; only the bars, back button, switches, press feedback and pull-to-refresh spinner change. Set Look to Android above to see it.

2. Typeface on the phone

  1. The system font (San Francisco / Roboto), which follows the phone's text size setting on iPhone
  2. Inter, as on desktop
Recommend 1. It's the single biggest "this is an app" cue, and it's free.

3. The ask docked in a session

  1. Compact: Allow once and More… (Always allow and Deny are one tap away, in the sheet)
  2. All three choices docked, as today
Recommend 1. It leaves room for the conversation and uses the same card as the inbox.

4. New session

  1. A sheet over the inbox (swipe down or Cancel to back out), Start above the keyboard
  2. The same sheet with Start top right, like Mail's Send
  3. A pushed page, as today
Recommend 1. Starting a session is a "compose" action, and the big Start is where your thumb already is.

5. Swipe actions

  1. Swipe left on a session to archive, with Undo
  2. Also swipe right on an ask to Allow once
  3. No swipe actions
Recommend 1. Never approve a command with a swipe; it's too easy to do by accident.

6. Return key in the message box

  1. Return adds a new line; the arrow sends
  2. Return sends
Recommend 1, as in Messages and the Claude app. The Run a command box is the exception: Return runs it.

7. "2 machines" in the inbox header

  1. A status line under the big title ("hangar and falcon online", amber when one can't be reached)
  2. Drop it; the Machines tab covers it
Recommend 1. Whether Fleet can reach your machines is worth a glance, but it shouldn't sit among the buttons.

8. Haptics on iPhone

  1. Use the hidden-switch trick (iOS 18 and later) for a few confirmations
  2. None on iPhone
Recommend 1, kept small. It's unofficial and could stop working, but then it simply goes quiet. The mockup uses it, so you can feel it.

What a web app can't do natively

  • Haptics on iPhone: there's no API. Only the unofficial switch trick above. Android has vibration, and Chrome only allows it after you've tapped the page.
  • Notifications on iPhone need Fleet on the Home Screen (iOS 16.4+). No Allow once button on the notification itself on iPhone (Android can show action buttons). No Live Activities, Dynamic Island, widgets or notification grouping.
  • Swipe back in Safari: Safari owns the left edge, so in a browser tab our swipe works from the middle of the page only. From the Home Screen there's no system back at all, so ours is the only one. Android's back gesture works through history.
  • Keyboard: no keyboard height or animation events; we follow visualViewport, which on iPhone updates as the keyboard settles, so the composer can trail the keyboard rather than ride it. Safari's form bar (arrows and Done) may still sit above the keyboard.
  • Status bar and launch: the Home Screen app picks its status bar style at launch; theme-color can't recolour it later on iPhone. The splash screen is one colour (light or dark, not both), unless we ship a startup image per iPhone size.
  • Sheets, push and pop are drawn by us, not the system: tuned to feel close (velocity, rubber band, detents), but not identical. iOS 26 glass is an approximation with blur; no refraction.
  • Browser bars: in a Safari tab the address bar doesn't shrink as you scroll, because the app scrolls inside itself (needed for the fixed bars and keyboard handling). From the Home Screen there are no bars.
  • Background: no background refresh; the phone may drop the page from memory, so Fleet must come back instantly from cache.

What does work: Home Screen icon and full screen, app icon badge (iPhone 16.4+ and Android), web push, the phone's dark mode, safe areas, momentum scrolling and rubber banding, and Dynamic Type through the system font.

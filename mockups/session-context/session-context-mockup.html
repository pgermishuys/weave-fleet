What a session is attached to

Sessions pick up context from several places: the GitHub issue or PR they were started from, links the conversation mentions, the branch they run on, the automation that launched them. Today that shows up in three different spots with three different styles, and some of it doesn't show up at all. This page lists every kind of attachment, shows the current UI as it renders now, and proposes one place for all of it.

Today and proposed

“Today” is a screenshot of the real client in Vite mock mode, with one PR and one issue loaded into the smart-links store and the CI and review lists expanded. “Proposed” uses the same data and Fleet's own theme values. It's interactive: click the header chips, expand the rows, send a failure to the agent.

Cleanup along the way

Found while tracing the code. Most of it can go first, with no visible change.

  • Remove the dead action toolbar from the right panel header It only renders when actionsLayout === 'toolbar', and the only provider passes "card". That leaves about 300 lines of abort, resume, rename, delete and fork handlers, two dialogs, and an extra GET /api/sessions/{id} on every session switch. session/SessionMetadataHeader.vue · use-session-detail-context.ts
  • Stop fetching smart links twice The header loads /smart-links/all, and so does useSmartLinks in the activity stream, for the same session at the same moment. SessionMetadataHeader.vue · use-smart-links.ts
  • Delete the orphaned smart links panel Only its own test imports it. It also carries a second copy of the refresh-ring SVG and CSS. plugins/builtin/smart-links/SmartLinksPanel.vue (+ test)
  • Fix the smart link row's structure The check list renders after the labels, away from its toggle. Rows line up using margin-left: -23px. The conflict warning is an emoji, and the hover-only buttons can't be reached on touch. plugins/builtin/smart-links/SmartLinkItem.vue
  • Poll GitHub from one place The client re-resolves the active session's links every 30 seconds while CiWatcherService polls every open PR link every 30 seconds on the server. Keeping only the server poll and pushing changes over SignalR removes the countdown ring, and it fits the push-based session list planned for the feel pass. use-smart-links.ts · CiWatcherService.cs
  • Treat the origin as a smart link, not a copy of one Match the origin to its smart link by URL and flag it, so the Context tab can show it under “Started from” instead of listing it twice. SessionOriginBadge.vue · stores/smart-links.ts

Suggested order

  1. Delete dead code and duplicate fetchesNo visible change. Makes the next steps smaller.
  2. Rebuild the smart link rowWorded status rows, visible Send to agent buttons, the check list under its own toggle, no negative margins.
  3. Add the Context tab and header chipsMerge the origin into it, show the branch in the header and automation starts in the tab.
  4. One server-side poller that pushes updatesRemoves the client timer. The footer shows when GitHub was last checked.
One decision for you

A tab or a pinned section? I made Context a tab, so it doesn't take height from Changes and Files, and the header chips give the at-a-glance status. The alternative is a collapsible section pinned above the tabs: always visible, but it takes 100–250px from every canvas.

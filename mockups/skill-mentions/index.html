Skill mentions in the composer

Proposal: type $ anywhere in a message to pick a skill. On OpenCode 2 only, skills could also show in the @ list. Built from Fleet's real composer, popup and chip CSS. Everything else in the composer stays as it is today.

1 Today vs proposed, same message

The user wants the agent to debug, then tidy. Today a skill has to start the message, as /name, and only one fits. With $, skills go wherever the sentence puts them.

Today · / at the start only
/fleet-debug The refund total is off by a cent on @src/api/refunds.ts. Once it's fixed, tidy it with $fleet-simplify

$fleet-simplify is just text. Whether it runs depends on the model noticing the name. A /fleet-simplify mid-sentence would be text too.

Proposed · $ anywhere
The refund total is off by a cent on @src/api/refunds.ts. Use $fleet-debug to find it, then tidy the fix with $fleet-simplify

2 Typing $

The list opens after $ at the start of a word, anywhere in the draft. It holds only the session's skills (Fleet's built-in ones and the folder's), with the same rows and keys as the @ list. A $ that matches no skill, such as $HOME or $5, stays plain text.

Just typed $
The refund total is off by a cent. Use $
Narrowing: $sim
…then tidy the fix with $sim
No match: $HOME
No skill named “HOME”. It stays as text.
Why is $HOME empty inside the test runner

The list closes at the next space, as the @ list does. Only picked skills become chips. A typed $fleet-debug that exactly matches a skill becomes one too.

3 What the agent gets

The sent message reads the same on every harness, with a chip for each skill. Only the wire format differs. Switch the harness at the top.

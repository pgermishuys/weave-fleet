Condensing Settings

Settings has grown to 15 pages, one switch per card. Below is today's screen and three ways to condense it. Each one builds on the one before. All four show the same settings, with invented data. Click around inside each window.

What's there today

15pages in one flat list, in no particular order
17 + 1switches and a select under Features, 10 of them Experimental
4places that handle updates: Harnesses, Machines, System, Weave
5pages with a choice per harness: Harnesses, Weave, Permissions, Browser, Workflows
3screens the menu can't reach: API keys, Plugin settings, GitHub

What I need from you

1. How far should it go?

Option 1 is a styling change only: every page gets lighter and Features splits in two. Option 2 also merges pages, going from 15 to 10 in 4 groups. Option 3 adds a first page of everyday settings and a search box. I recommend 2 now and 3's search box next: it's the settings-search proposal from 14 October, and the shared row component in 1 is what makes search possible.

2. Where do experimental switches live?

All in Labs (shown): one list to try things, and graduating an experiment means moving one row to its page. Or in the page they change, with an Experimental pill: Jobs in Machines, Dreaming in Memory, Copilot in Harnesses. That's less action at a distance, but the experiments end up scattered again.

3. Does Weave go inside each harness?

Shown that way: Weave's plugin and config sit in each harness's tab, because Weave is per harness. The cost is that Weave's config editor, which is big, becomes a dialog opened from there.

4. Can the descriptions get shorter?

Rows show one line, and More opens today's full text. Most of today's text stays word for word behind More; only the first line is rewritten.

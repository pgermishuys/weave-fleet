      Every panel is a canvas tab
      Step 1
      
        
      Changes, Files and the diagram stop sharing one viewer. Each session keeps its own ordered list of open canvases, like t3code's right-panel surfaces. The fake __visual__/ file paths go away.
      
        viewMode + __visual__/ paths → canvases[] + activeCanvasId
      
      2. 
      
    2. 
        
      2
      The agent opens and edits canvases
      Step 2
      
        
      Instead of returning a one-off picture, the agent calls canvas tools. It can change the same diagram later. Press Agent revises: it removes the poll and draws the planned push edge without starting over.
      
        visualize(type, content) → canvas_open · canvas_patch
      
      3. 
      
    3. 
        
      3
      Your edits go back to the agent
      Step 2
      
        
      Drag a box or remove one, and the canvas counts your edits. On its next turn the agent reads them. Click a box and Ask agent to attach it to your message, the way markdown annotations work today.
      
        canvas_read(id, since) → state + your edits
      
      4. 
      
    4. 
        
      4
      A terminal you share
      Step 3
      
        
      A real shell on the server, shown with xterm.js over SignalR. The agent can run commands in it, so you watch the tests it runs instead of reading a collapsed Bash card.
      
        server PTY · SessionEventsHub stream · terminal_run
      
      5. 
      
    5. 
        
      5
      Room when a canvas needs it
      Step 1
      
        
      Diagrams and boards need width that a file list doesn't. Widen gives the active canvas most of the sheet, and the conversation stays visible beside it.
      
        452px → 760px, per canvas type
      
      6. 
      
    6. 
        
      6
      Canvases from a repo or your home folder
      Step 4–5
      
        
      Open + to see built-in canvases, the ones a project commits under .weave/canvases and your own. Repo canvases ask for trust first and run in a sandboxed frame. Browser comes last, and only in the desktop app.
      
        canvas.json + index.html · sandboxed iframe · postMessage SDK

    How the pieces connect
    
      
    Canvas state lives on the server, so every harness can reach it and it survives a reload, a second window or a remote client.
    
    
    
    
    
      
    
        
    Canvas host
    
        
    client/src
    
        
      
          
    • Tabs per session, replacing SessionsV2RightPanel's fixed stack
      • 
          
    • Built-in canvas types are Vue components in a registry
      • 
          
    • Other canvases run in a sandboxed iframe with a small postMessage SDK
      • 
        
    
        ↔ SignalR: canvas.updated
      
    
      
    
        New
        
    Canvas store
    
        
    WeaveFleet.Application
    
        
      
          
    • Canvas instances per session, with versioned state
      • 
          
    • Records who changed what, you or the agent
      • 
          
    • Checks every patch against the canvas's JSON Schema
      • 
        
    
        ↔ canvas_* tools
      
    
      
    
        New
        
    Canvas MCP server
    
        
    WeaveFleet.Api
    
        
      
          
    • One per session, added to every harness Fleet starts
      • 
          
    • Generic tools: list, open, read, patch, focus
      • 
          
    • Built-in types can add their own, like terminal_run
      • 
        
    
        ↔ MCP

    A canvas in a repo.weave/canvases/release-checklist/canvas.json
    

    {
  "id": "release-checklist",
  "title": "Release checklist",
  "icon": "list-checks",
  "entry": "index.html",
  "state": { "schema": "./state.schema.json" },
  "agent": {
    "describe": "Steps from RELEASE.md for one version.",
    "tools": ["read", "patch"]
  },
  "permissions": { "network": false }
}
    
      
    
      
    
        
    What the agent getsMCP tools, one server per session
    

    canvas_list()                  → open canvases, types, versions
canvas_open(type, state?)      → { canvasId, version }
canvas_read(canvasId, since?)  → state + your edits since then
canvas_patch(canvasId, ops[],  → JSON Patch, checked against
             ifVersion)          the schema; fails if stale
canvas_focus(canvasId)         → bring its tab forward

# added by built-in types
terminal_run(command)          → runs in the Terminal canvas
browser_open(url)              → desktop app only

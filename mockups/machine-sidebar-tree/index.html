Machine jumps to the top Our choice

The sidebar puts the live machine first. I made that call in #326 and offered home-first as the alternative. Nothing technical depends on it. A fixed order (home, then machines in the order you added them) is a one-line change, and the Live tag moves instead of the machine.

No projects on other machines Our choice

Other machines were built as a light "last list we polled" (#320), drawn by their own small component. The list Fleet already fetches from them names each session's project (projectId, projectName); the sidebar ignores it, and the offline cache strips it. To show the full tree we also fetch that machine's /api/projects (for order and empty projects) and draw it with the same project groups the live machine uses.

Opening one reloads the page Real constraint

The app works against one machine at a time. The API client, the live event connection, and the stores for sessions, projects, workflows, running work and harnesses all point at that one machine. Switching reloads the page so no store can mix two machines' data. Removing the reload means letting the session you open talk to its own machine while the rest of the page stays put. That's Step 2, and it's the big piece.

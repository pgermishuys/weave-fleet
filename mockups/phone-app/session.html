A session on the phone

One session from start to finish: the agent is working, you queue a follow-up, it asks to run a command, it asks you a question, then it finishes with a pull request. Click through it on the phone, or use the steps on the right. Everything you can tap is live.

Also try: the folded steps row, the + button, the agent and model chips, the plan bar and the ⋯ menu.

The rules behind it

Six decisions the prototype makes

The bottom is for whatever needs you

When the agent asks, the ask takes the composer's place at the bottom, where your thumb is. Once you answer, the composer comes back.

The header is the status

Machine, state and elapsed time, always visible: Working · 1m 12s, Needs you, Finished. The plan bar sits under it when there is one.

A turn's tool calls fold into one row

"Read 4 files · edited 1 · ran 1 command". Tap it for the list, then a step for its diff or output. Text from the agent stays in the conversation.

Sending while it works queues

The send button says Queue while the agent works, and the message waits above the composer until the turn ends. Send now steers the agent mid-turn, if the harness supports it.

Settings live behind chips

Agent, model and effort are chips above the keyboard while you type. Each opens a sheet, not a dropdown. Attachments, @ files, ! commands and /btw are behind +.

What a phone can't do well opens elsewhere

Terminal, the editor and app previews say so and offer the computer. Diffs and files are read-only sheets. One-off ! commands still work.

Terminal

Terminals need a keyboard and a wide screen, so they open on the computer. On the phone you can run a one-off command and see its output in the conversation.

! git log --oneline -3

Runs in the session's folder, no model turn.

Something the phone doesn't doIt says why and offers the closest thing that works: a ! command, or a handoff to the computer.

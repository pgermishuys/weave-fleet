Pick the machine a new project goes on

Today the sidebar's New Project button (folder +) always creates the project on the machine you're working in: the desktop app's own machine, unless you used Work here on another one. Other machines' projects show in the sidebar, and you can already start a session on another machine, but you can't add a project there.

This proposal adds the same Machine chip the new-session box has to the New Project dialog, plus a New project on … item in each machine heading's menu. A project is still just a group of sessions on one machine. Nothing changes about folders.

How it behaves

  • Machine chip (“Create on”) shows only when Fleet knows more than one machine. With one machine the dialog looks exactly as it does today.
  • The folder + button starts on the machine you're working in. New project on build-box from a heading's right-click menu starts on that machine. You can change either in the chip.
  • Unreachable machines are listed but can't be picked, as in the new-session box.
  • After Create Fleet asks that machine for its list again, so the new (empty) project shows at once under its heading, and the heading unfolds. It doesn't wait for the next poll.
  • If the machine stops answering mid-create, the dialog stays open with the name kept and says which machine it couldn't reach, not “Failed to fetch”.
  • Phone: the same dialog. The chip opens its menu full width.

Under the hood: useCreateProject already takes its machine from useMachineTarget(). The dialog gives it the picked machine (targetFor) and then calls machines.refreshMachine(key). No server change and no migration.

What I need from you

  1. Both pieces (chip in the dialog and “New project on …” in the heading menu), or just the chip? I recommend both. The heading menu already has “New session on …”.
  2. Should the projects' own menu (rename, move, delete) on another machine also get “Move to another machine”? I'd put that on the Later list. Moving would mean moving sessions between machines, which is a much bigger change.

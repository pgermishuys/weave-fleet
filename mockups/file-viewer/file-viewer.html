Better file viewer

Reading a file in the panel means scrolling sideways, dragging past the edge to select a long line, and losing the tree every time a file opens. Every frame below is drawn at Fleet's real sizes: a 360 px panel, Fleet's editor font and gutters, on the same made-up file. Each option has a Today and a Proposed view so you can compare them.

What's wrong today

Found in the code, not guessed. Try it in the frame: select line 18 to its end, or press Widen.

  1. No soft wrap.The editor (lib/code-editor/editor-extensions.ts) never adds EditorView.lineWrapping. After the line-number, fold and change gutters, about 38 characters fit in a 360 px panel; most lines of this file are longer.
  2. Selecting a long line fights the scroll.You drag past the right edge and wait for autoscroll. The "Add lines to message" chip hides on any scroll (@scroll.capture="hideChip" in FileCanvas.vue), so it's gone once you've scrolled sideways, and it sits at the selection end, which is often off-screen.
  3. Line numbers do nothing.No click-a-number, no shift-click range, no highlight that stays put. To point the agent at lines 21–27 you drag across the text.
  4. Widen hardly widens.It's capped at 760 px and always leaves the conversation 480 px (AppShell.vue). On a 1440 px window with the session list open, Widen gets about 610 px; dragging the gutter stops at half the window.
  5. The tree disappears when a file opens.Files and the file share one canvas: a click opens a preview tab, and the tree is a tab away. Going up a folder means going back and finding your place again.
  6. The path bar is just text.Breadcrumbs can't be clicked, and below 430 px of panel the folders are hidden, so you can't see where you are.
  7. The tree is mouse-only.Folder rows are click-only <div>s (FileBrowserTreeNode.vue): no Tab stop, no arrow keys. 16 px of indent per level pushes deep names off the edge.
  8. Search results lose the file name.Results show the full path with an ellipsis at the end, so in a narrow panel the part you need is the part that's cut.
  9. Go to file (Ctrl P) is half there.Empty, it lists only the open tabs: no recent files, no @symbol, no :line. Nothing in the panel says it exists.
  10. Phone is the worst case.The panel becomes a full-width sheet, but it still doesn't wrap: every long line is a sideways swipe, and the selection handles drift off-screen.

ARead it in the panel

Small fixes inside the 360 px panel: wrap, pick lines by their numbers, and do something with them.

Try: click line 18's number, shift-click 27, then Add to message. Toggle wrap with the button or Alt Z. Drag down the numbers to pick a run of lines.

How it behaves

  • Wrap toggle in the file bar, Alt Z. On by default in the panel; your choice is remembered per file. Wrapped lines hang under their start, with a faint guide.
  • Click a line number to pick the line, shift-click to extend, drag down the numbers for a run. The pick stays highlighted while you scroll and survives a click in the text.
  • A bar at the bottom names the range and offers Copy link (path:21-27), Quote (a fenced block with the path) and Add to message. It replaces today's floating chip, so scrolling never hides it.
  • Selecting text still works the way it does now.

Trade-offs

  • Wrapped code can be harder to scan for indentation; the hanging indent and guide offset most of it, and the toggle is one key away.
  • Doesn't give you more room. A wide table or a minified file still wants a bigger view (B).
  • Adds one more control to an already busy file bar; it collapses to an icon below 430 px.

Cost

~4 files~350 lines + ~200 tests1 PR

editor-extensions.ts (wrap compartment + gutter click handlers), new line-range.ts (range field and highlight), FileCanvas.vue (toggle, range bar replaces the chip), stores/canvases.ts (wrap per file). CodeMirror does wrap and gutter events natively.

Recommended, first

BFocus: let the panel take the room

Widen becomes Focus. The panel takes the session list and the conversation; the conversation folds into a strip that still shows the agent working.

Try: press the Focus button at the top right of the panel, or Ctrl Shift ↵. Esc or the strip brings the conversation back. Compare the width badge with Today's Widen.

How it behaves

  • One button where Widen is now, and Ctrl Shift ↵ (rebindable, free in Fleet's keymap today).
  • The panel fills everything right of the rail. The conversation becomes a 46 px strip: the session's status dot and title, and a button back.
  • Esc (when the editor doesn't need it), the strip, or the button again puts every panel back at the width you left it.
  • Works for every canvas, not just files: Changes, Browser and Page canvases get the room too.
  • On a phone the panel is already full screen, so the button isn't shown.

Trade-offs

  • You can't read the agent's reply while focused; the strip only says it's working. Add to message still works (the pill waits in the composer).
  • Retires Widen's middle step. Anyone who liked 610 px still has the gutter drag.
  • Doesn't fix wrap or line picking on its own; a 1,100 px view still scrolls on a 180-character line.

Cost

~5 files~250 lines + ~150 tests1 PR

AppShell.vue (a focused width beside the widened one), stores/canvases.ts (widened becomes focused), CanvasHost.vue (button), new ConversationStrip.vue, keybinding-types.ts. The panel already resizes; this is a third width.

Recommended, with A

CPop the file out

Open a file in a large view over the whole window, with its own tree on the left, like a light editor. On the desktop app, also in a window of its own.

Try: press Pop out in the file bar. Pick files in the tree on the left (arrow keys work). Esc closes it.

How it behaves

  • Pop out button in the file bar. The view covers the window with a tree beside the file, so you browse without losing your place.
  • Esc closes it; the panel shows the file you ended on.
  • Desktop app: "Open in new window" puts the same view in its own window, for a second screen.

Trade-offs

  • Hides the conversation completely, and it's a second place where files open, with its own tabs to keep in step.
  • A file's buffer drives one editor at a time (FileBufferRecord.view), so the overlay must borrow the panel's editor or both need to share one buffer safely.
  • A second window needs its own route, sign-in and SignalR connection in Electron.
  • Most of what it gives, B gives with less: B is the same room without a second place.

Cost

~8 files~900 lines + ~300 tests (overlay)+ ~600 for a window

New FileViewerOverlay.vue hosting the tree and an editor, changes in buffers.ts to hand the editor between views, and for the window: an Electron BrowserWindow, a route and a connection of its own.

DGet around without the tree

Make the path bar a menu, give Go to file recent files, symbols and lines, add an outline, and let the tree work from the keyboard.

Try: click invoices or ledger in the path bar to jump to a neighbouring file. Press the outline button, or Ctrl P in the frame and type @rec or :40. In the Files tab, use the arrow keys.

How it behaves

  • Every folder in the path bar opens a menu of what's beside it. In a narrow panel, the middle folders fold into … instead of disappearing.
  • Ctrl P opens on your recent files for this session. @ lists the symbols in the file, :40 goes to a line. A search icon in the panel header says it's there.
  • Outline button: the file's functions and types, from CodeMirror's syntax tree. Picking one scrolls there and flashes the line.
  • Tree rows become real buttons: ↑ ↓ move, → opens a folder, ← closes it, Enter opens the file. Search results lead with the file name.

Trade-offs

  • Doesn't touch the scrolling or line-picking problem: it's about getting to the file, not reading it.
  • Symbols only for languages CodeMirror parses in Fleet today (TS/JS, C#, Python, Markdown headings, and so on); other files have no outline.
  • Recent files need a small per-session list in the store (no server change).

Cost

~6 files~550 lines + ~250 tests2 PRs

FileCanvas.vue (crumb menus, outline), GoToFileDialog.vue + stores/go-to-file.ts (recent, @, :), new lib/code-editor/symbols.ts, FileBrowserTreeNode.vue (roving focus), FileBrowserPanel.vue (results). Path menus reuse useFileBrowser's folder listing.

Second step: path menus + recent first

Recommendation: A, then B, then the cheap half of D

A fixes what you hit every time (wrap, picking lines). B gives the room when a file really is wide. D's path menus and recent files make getting to the next file quick. Skip C: B covers it with one place for files instead of two.

Try everything at once: pick lines, wrap, Focus with Ctrl Shift ↵, the path-bar menus and Ctrl P.

The order I'd build it

  1. A: wrap toggle, line numbers that pick lines, the range bar. One PR, ~550 lines. Demo: pick lines 18–27 in a 360 px panel without scrolling sideways and send them to the agent.
  2. B: Widen becomes Focus with the conversation strip. One PR, ~400 lines. Demo: Ctrl Shift Enter, read the file at full width, Esc back.
  3. D, cheap half: path bar menus with the … fold, recent files in Ctrl P, the search icon, file name first in results. One PR, ~450 lines.
  4. Later list: outline and @symbol, keyboard tree, pop-out window.

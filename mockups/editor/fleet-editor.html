Four places for an editor

Try it Fleet theme

Type in the editor and press Ctrl S to save. Select a few lines to add them to the message. For completion, type ver (words in the file), try (a snippet) or from "../ (paths in the repo). To see the conflict bar, change auth.ts first and then press Agent edits auth.ts.

How you get there

Click a file in Files, as you do today. The code is editable straight away and Ctrl S saves. The File/Diff switch stays; Diff becomes editable, so you can revert one hunk of the agent's change.

Why it fits

It's the smallest change. CanvasFileViewer swaps its fenced-code block for the editor and nothing else moves. The tree stays in view while you work.

Watch out

One file at a time, in the bottom half of a 440 px panel. Widen helps, but it's a viewer that learned to type, not a place to work.

Rough size: 2 days, save endpoint included

How you get there

Click a file in Files or Changes, or press Ctrl P anywhere in the session. One click opens an italic preview tab that the next click replaces; typing in it or double-clicking keeps it. The dot on a tab means unsaved.

Why it fits

It reuses what the canvas already does: overflowing tabs, KeepAlive (your undo history survives switching tabs), the accent pulse when a tab updates, and Widen. A file opened from Changes opens straight in Diff.

Watch out

The tab strip gets busy next to Changes, Files, Progress and Browser. Preview tabs and KeepAlive's 8-tab cap keep that in check.

Rough size: 3–4 days

How you get there

Double-click a file tab, or Ctrl E. The tree, your file tabs and the terminal drawer come with you; the conversation keeps working in the right column. Ctrl E again puts the chat back in the middle.

Why it fits

This is the lightweight IDE: tree, tabs, editor, terminal and the agent on one screen, inside the same session. It's option B's tabs and editor in a different layout, not a second editor.

Watch out

A second layout to maintain, and on a phone it's just B. Worth building once people actually edit in Fleet, not before.

Rough size: 3 days on top of B

How you get there

Click an Edited or Wrote row in the conversation, or a file in Changes. The agent's change opens inline as an editable diff: reject a hunk, tweak a line, save.

Why it fits

You fix the change where you noticed it, without moving over to the canvas. Good for the edit that is almost right.

Watch out

An editor inside a scrolling conversation fights the scroll and the stick-to-bottom behaviour; allow one peek at a time. Better as a follow-up to B than a first step.

Rough size: 2 days after B

Markdown and HTML keep their rendered view

They open rendered, as they do today, with Rendered · Source · Diff in the tab's bar. Rendered shows your unsaved edits, not only what's on disk, so you can write a README and check it before saving. Rendered Markdown keeps today's annotations, and HTML still renders in a sandboxed frame. Opened from Changes, a file starts in Diff. Try docs/auth.md and public/status.html in frame B.

What every option does the same way

The agent edits a file you have open

If you haven't changed it, the editor updates in place: the new lines flash, keep an indigo stripe in the gutter, and the tab pulses. If you have unsaved changes, nothing is overwritten. A bar offers Compare, Keep mine or Use the agent's.

Saving can't clobber the agent

Save sends the hash of the file as you opened it. If it changed on disk since, the server refuses the write and you get the same bar. The agent isn't told anything: it reads files from disk, and OpenCode already makes it re-read a file that changed since its last read. No tokens are spent on your edits.

Asking about lines

Select lines and choose Add to message. The composer gets @src/middleware/auth.ts:14-18 as a reference pill, the same pill @ mentions make. Nothing is sent until you send it.

On the phone

CodeMirror is built for touch, so the file opens full height in the phone sheet with the same Save and the same conflict bar. Monaco doesn't support mobile browsers, which is one reason it isn't my pick.

CodeMirror 6 or Monaco

Monaco's one real advantage is TypeScript IntelliSense out of the box, and only for TypeScript and JavaScript. Fleet sessions run in C#, Go and Python repos too, so real code intelligence needs a language server either way. CodeMirror is about a twelfth of the download, works on the phone, and picks up every Fleet theme through the CSS variables the app already has.

What option B takes

Work

  • Save endpoint. PUT /api/sessions/{id}/files/content with the hash you opened; 409 with the current text if the file changed. It refuses truncated and binary files, which the read endpoint already flags.
  • Knowing when a file changed. Open editors listen to whatever refreshes the Changes canvas. I haven't checked how live that refresh is; if it polls, the editor also re-checks the hash when its tab comes back into focus.
  • Client. A file kind in canvas-registry.ts, FileEditor.vue as a lazy chunk, and the existing Markdown and HTML renderers behind the Rendered switch.

Decided

  1. B, files open as tabs.
  2. Markdown and HTML open rendered, with Rendered · Source · Diff.
  3. No agent tool for opening files. The agent never opens tabs; you do. Clickable file:line paths in its replies could come later, as separate work.

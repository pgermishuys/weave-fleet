Right Panel Prototypes

Three creative directions for the Files / Preview / Details tabs and diff view in Weave Fleet. Grounded in prior-art research covering VS Code, Zed, GitHub, Cursor, Claude Code, Graphite, and Linear.

The problem, in one paragraph

The right panel today has three flat tabs (Files, Preview, Details) and a persistent bottom diff drawer. In practice, Preview is empty until you click a file, Details holds real content (todos, PR/issue links, session actions) but nobody opens it because the conversation header already carries the main actions, and the diff shows in two places — inline in Preview and in the bottom drawer — which is redundant. There's also no distinction between "browse the whole tree" and "review what the agent just changed."

Principles the research settled

Split browse from review. A generic file tree is for exploring. A changed-files list is a different object.
Metadata doesn't belong behind a tab. Todos, linked PR/issue, session actions live in a persistent strip, not competing with Files for a click.
Scale picks the diff shape. One file changed wants inline. Many files want an aggregate multi-file view.
Every changed file has reviewed state. Turn the change list into a checklist, not just a menu.
Live-following ≠ deliberate review. Auto-shift the highlight within a stable structure. Never auto-swap the entire layout.

The three prototypes

Prototype A

Contextual (no tabs)

Panel modes shift with what you're doing. Metadata strip stays put on top. Diff renders inline where the file is selected. Most opinionated.

 Prototype B

Files + Changes

Two tabs modeled on VS Code Agents: a browse tree and a promoted changed-files list with per-file review state. Persistent metadata header. Safest bet.

 Prototype C

Files + slide-over peek

Tree only. Selecting a file peeks a preview over the conversation. A separate full-width "Review changes" mode handles diffs. Boldest, most VS-Code-like.

How to read these

  • Each prototype shows a plausible slice of the app so you can see how the right panel behaves in context.
  • Interactive bits: try clicking files in the tree, review toggles, mode buttons, drawer states.
  • Session list and conversation are intentionally low-detail — they're not what's being redesigned.
  • Colors and typography match the current app, so this reads as an evolution rather than a repaint.

Recommendation, if you want one

Prototype B is the safest, most-validated direction. It maps one-to-one onto VS Code's Agents window (the closest peer product to Weave Fleet), moves the redundant Details tab into a header where it stops competing for clicks, and gives per-file review state — which the research flagged as the single most-repeated "works well" pattern.

Prototype A is more opinionated but riskier. The "auto-shift" idea only works if you keep the underlying structure stable and only shift emphasis, not layout. Done right it feels magical; done wrong it destroys scroll position.

Prototype C is worth building if you're planning to make full-diff review a first-class mode (like a lightweight PR review view). The slide-over is a good match for casual peek-and-close file reads that don't warrant taking over the panel.

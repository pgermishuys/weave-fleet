References: let every session read the folders and repos you work next to

OpenCode 2 can list named folders and Git repositories to the agent as "references". I ran it, OpenCode 1, Claude Code and the pieces Fleet would need, against a scripted model on scratch homes. This page is the verdict, mockups in Fleet's look, how it would work for each harness, the evidence and a plan. The mockups follow your theme.

Viable, with conditions

It's cheap and every harness Fleet runs can have it: about 24 tokens plus 50–70 per reference, in the cached part of the prompt. OpenCode 2 and OpenCode 1 both have it built in, Claude Code has --add-dir, and Pi can be told by Fleet. Three conditions, all proven live:

  1. Fleet keeps the list per repository and hands it to each session. OpenCode's own references setting is per server (Fleet shares one server across repositories) or lives in the repo's opencode.json.
  2. Fleet sets the permissions. On OpenCode 2 a reference grants nothing: reads still ask, and at Fleet's default level the agent wrote into one. Fleet adds a rule per reference: read freely, never edit.
  3. Fleet clones Git references. OpenCode clones with plain git, a separate copy per harness, and a failed clone is only a log line while the agent is still told the folder exists.
Once per repository

Name the folders you work next to

For weave-fleet, that's ~/source/weave and OpenCode's source. Add them with a short description. Fleet suggests sibling folders, but adds nothing on its own.

Every session in it

The agent knows where to look

Each session in that repository starts with the list: name, path, description. A chip on the new-session page lets you drop one or add another for this session only.

Read, not write

It reads with its own tools

Read, grep and glob work in a reference without an "outside folder" ask. Edits there are refused. Every read shows in the conversation with the reference's name on it.

Why bother: what happens today

The agent doesn't know the sibling repository exists. It guesses a path, asks, or you paste one into the message. At Fleet's Ask and Edits levels, every read outside the session's folder raises an "outside folder" question (checked live on OpenCode 2). In this repository's own Claude Code history, 28 of 215 sessions reached into ~/source/opencode and 23 of 215 into ~/source/weave, each time by path typed into a prompt or a note.

A sibling repository the work depends on

Fleet installs the Weave adapter. "Does the adapter still default to Loom for subagents?" is a grep in weave, if the agent knows where weave is.

An upstream library's source

OpenCode 2 changes weekly. A Git reference to anomalyco/opencode on branch v2 keeps a fresh copy that every session can read, refreshed daily.

A design system or docs repository

Tokens, icons and brand rules live in weave-assets. A UI session reads the real values instead of inventing a near match.

A folder of specs

Product notes in a plain folder, not a repository: a local reference works for any folder.

Next to Sources

The two proposals split the user's goal ("pull context from GitHub, Linear, Google Docs") by where the context lives. They share the rail item and the read-only promise.

References (this spike)

Files on this machine: local folders and Git repositories.

The agent reads them with the tools it already has (read, grep, glob). Fleet only tells it where they are and sets the permissions.

Kept per repository. Costs ~60 tokens per reference, per request, cached.

LSources (proposal of 1 October)

Hosted services: Linear, Notion, Drive, HubSpot, GitHub issues.

Fleet signs in and offers two read-only tools, sources_search and sources_read, or you attach a document.

Kept per Fleet. Costs ~170 tokens of tool descriptions.

What Fleet stores

  • Per repository: name, a folder or a Git repository and branch, a description, and Can change files (off by default).
  • A reference without a description isn't shown to the agent by OpenCode, so Fleet requires one.
  • Worktrees share their repository's list, the way OpenCode 2 itself resolves it (checked live).

Suggestions, never automatic

  • Fleet looks for folders next to this one under the workspace root, and for repositories named in the README or AGENTS.md.
  • A suggestion is a row you click. Nothing reaches the agent until you add it.

Git references

  • Fleet clones once per machine with its GitHub sign-in and shows what happened. OpenCode would clone a separate copy per harness, silently.
  • Couldn't clone rows are left out of the agent's list. OpenCode 2 still lists them, at a path that doesn't exist.

2 · Pick for one session

The new-session page gets a References chip next to Folder and Harness. It starts with the repository's list. Untick one to leave it out, or add a folder for this session only. Switch the harness to see what changes.

What should we work on?

Check whether the Weave adapter still defaults subagents to Loom, and update our docs if it changed.

Not the same as @

  • @ (PR #205) puts one file or folder into one message.
  • A reference is standing context: the session knows the folder for its whole life, and may read it without asking.

Mid-session changes

  • OpenCode 2 tells a running session about a change as a short update and keeps its system prompt, so the prompt cache survives (checked live).
  • OpenCode gets the same update through Fleet's note on the next message. Claude Code and Pi pick it up when Fleet next starts their process.

3 · The agent reads a reference

Reads in a reference carry its name. An edit there is refused and shows as refused. The References chip in the header lists what was read. Open "What the model sees" for the exact text, then switch harness.

    Read-only, and where it stops
      
        
    • Fleet adds deny rules for edit and write in each reference, at every permission level. Checked live on OpenCode 2, OpenCode and Claude Code.

    How it works
    OpenCode 2's side as it is in 2.0.18, then what Fleet adds. The token figures are counted on the real text.
    
    
    
      
    OpenCode 2's side
    
        
    Config: references maps a name to a path, or to { repository, branch, description, hidden }.
    
        
    Prompt: references with a description go into the system prompt after the skills list, as <available_references>. Without a description they're left out. hidden only hides one from OpenCode's own @ menu; the model still sees it.
    
        
    Access: nothing extra. Read, grep and glob take absolute paths, and an outside folder asks external_directory, reference or not.
    
        
    Git: git clone --depth 100 into ~/.local/share/opencode/repos/host/owner/repo[@branch]; fetch and hard reset once a day.
    
        
    Changes: a running session gets a <system-update> with only what was added or removed; its system prompt doesn't change.
    
      
    Fleet's side
    
        
    Store: references per repository in Fleet's database, plus per-session additions and removals made in the composer.
    
        
    Tell the agent: Fleet renders the same block OpenCode 2 uses, and hands it to each harness its own way (see Harnesses). On OpenCode 2 that's a per-session instruction entry, which is cache-safe and sends a diff when it changes.
    
        
    Permissions: per-session rules: allow external_directory for <path>/*, deny edit, write, patch and move there.
    
        
    Git: Fleet clones with its GitHub sign-in into ~/.weave/references, refreshes daily, shows status and errors, and passes a plain folder path to every harness.
    
        
    Show it: tool calls whose path is inside a reference get its name in the conversation, and the header chip lists the reads.
    
    
    

    
    The exact text the model gets
    
    
    Fleet's version for the two references in the mockups. OpenCode 2 and OpenCode 1 render the same shape themselves.
    
    
    

    
    Token cost per request
    
    
    Counted with the Claude tokenizer on the rendered text. It sits in the system prompt, so after the first request it's read from the prompt cache. For scale: OpenCode 2's whole system prompt in the test was about 5,000 tokens.

    Capability
      
        
    • One flag, SupportsReferences, plus ReferencesReadOnly. Pi has the first and not the second, so the UI says "Pi can change files in references" next to the chip.
      • 
        
    • OpenCode 1 and OpenCode 2 each do it in their own adapter; nothing shared, as with every other feature.
      • 
      
    
      
    Why not OpenCode's own setting
      
        
    • Fleet runs one OpenCode server for many repositories. A references setting in Fleet's server config would apply to all of them.
      • 
        
    • The other place is the repo's opencode.json. Fleet doesn't write into your repository. References you already keep there still work, and Fleet can list them as "from opencode.json".

    Questions for you
    
    
    
      
    1. Where does the list live?Per repository, with per-session changes in the composer (what the mockups show), or also a machine-wide list for things like ~/source/opencode that every repository wants?I'd start per repository; a machine list is easy to add later.
    
      
    2. Read-only by default?The mockups refuse edits in a reference unless you turn on "Can change files". Or should references be writable like any other folder, as OpenCode does?I'd keep read-only by default; the shell gap is stated plainly.
    
      
    3. Who clones Git references?Fleet, with its GitHub sign-in and visible status, or leave it to each harness (OpenCode 2 and OpenCode only; Claude Code and Pi can't)?I'd have Fleet clone them.
    
      
    4. Pi without read-onlyOffer references in Pi with the "Pi can change files" note, or turn them off for Pi?I'd offer them with the note.
    
      
    5. Where in the UI?Under the repository in the Sources rail item (mockup 1), or in the repository's own settings, reached from its row in the session list?Sources, so all context is in one place, with a link from the repository row.
